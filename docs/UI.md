# UI 设计说明

这份文档讲两件事：**现在的结果长什么样、为什么这样是对的**，以及**要做专门卡片时具体怎么接、按什么视觉规范做**。

## 1. 现状：不加 UI，就是最对的 UI

DSH 内置的 Web Client **不消费** `presentCall` / `presentResult`（官方 `docs/cookbook/adding-a-tool.md` 明确写了）。工具结果走的是原生工具结果行：一行标题 + 参数折叠 + 结果内容。

所以现在 `dsh-bean` 在 DSH 里的样子，就是 DSH 自己的样子 —— 它不可能不协调，因为没有任何一处是它自己画的。

这不是偷懒，是取舍：一个第三方插件自带一套视觉语言，是长期负债。DSH 还在 developer preview、明说了会有破坏性变更；今天对齐得再细，主题令牌一改就全歪。先把能力接进去，等 UI 契约稳了再做卡片。

## 2. 要做专门卡片时，接在哪里

Client 插件（浏览器侧），占 `tool.call.toolview` 这个 keyed slot，用**线上工具名**注册：

- Host 侧（`index.js`）声明 `presentCall` / `presentResult` **不会**长出卡片 —— 那只影响支持这套投影的 UI。
- 卡片必须放在 Client 插件里，React 组件，props 从 `ToolCallBlock` 来：`arguments`、`content`、`error`、`metadata`（即持久化的 `result.meta`）、PTC 的 `parentCallId`、Session path 事实。
- **必须本地校验入参**，遇到畸形或不支持的输入返回通用行 —— 卡片永远不能让回放崩掉。
- 想在结果里带结构化事实（比如命中命中词位置、每条录音的 id/时间/时长），用 `output.presentationMeta(args, value)` 投影出来，它会随 `tool/result` 落盘。我们的 `output` 里已经带了 `library`（就是 MCP 的 `structuredContent`），投影直接用这个，不需要额外请求。

> 不要为了卡片去改工具返回值，也不要把 React props 塞进 metadata。

## 3. 视觉规范：贴着 DeepSeek 的审美基线

DSH 的界面语言是**克制的信息密度**：单一强调色、靠留白和分隔线分层、几乎不用阴影、动效只做淡入。照这个做，卡片天然属于那里。

### 色

| 角色 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| 强调色 | `#4D6BFE` | `#4D6BFE` | DeepSeek 品牌蓝，只用于链接、选中、关键数字 |
| 正文 | `#1A1A1A` | `#E8E8E8` | |
| 次级文字 | `#6B6B70` | `#9A9AA0` | 时间、时长、场景 |
| 分隔线 | `rgba(0,0,0,.08)` | `rgba(255,255,255,.10)` | 优先用它分层，不要用阴影 |
| 卡片底 | `#FFFFFF` | `#1C1C1E` | 与对话底色只差一档 |

**一条硬规则：强调色只出现在一个地方。** 一个卡片里两处蓝，就没有重点了。

### 字

- 字族：系统 UI 栈 + `"Noto Sans SC"` 兜底中文
- 正文 14px / 1.6；卡片标题 15px / 600；次级 12.5px / 500
- 等宽只在真需要对齐时用（时间轴、id），不要拿来装技术感
- 中文不加字距，英文数字用 `font-variant-numeric: tabular-nums`

### 尺寸

- 间距全用 4 的倍数：卡内 12/16，条目间 10，段落间 16
- 圆角 10px（卡片）/ 6px（chip）
- 边框 1px 低对比；**不用 box-shadow**，需要浮起来才用一档极轻的
- 动效 120–160ms `ease-out`，只做透明度 + 2px 位移；不做弹跳、不做缩放

### 卡片的信息层级（`bean_recall`）

```
┌────────────────────────────────────────────┐
│ 检索范围：上周（11-03 ~ 11-09）   命中 2 条   │  ← 14px/600，条数用次级色
├────────────────────────────────────────────┤
│ 11-04 15:20 · 会议 · 38分      ← 12.5px 次级 │
│ 渠道定价沟通                    ← 15px/600   │
│ ……首年 6 折、次年回到 7.5 折，渠道要求把返点  │  ← 2 行截断，命中词加底色
│ 从 8% 提到 10%……                            │     （不加粗不变色）
├────────────────────────────────────────────┤
│ 查看全文 · 在 App 中打开         ← 12.5px 蓝 │
└────────────────────────────────────────────┘
```

- 命中词高亮用 **底色**（`rgba(77,107,254,.12)`），不用加粗/变色 —— 加粗会破坏正文节奏。
- 片段只显示 2 行，`text-overflow: ellipsis`；完整原文点「查看全文」（`bean_get`）。
- 空结果要区分两种：**窗口内没录音** vs **窗口内有录音但没提到这些词**。这是搜索类 UI 最容易糊弄过去、用户最恼火的地方，后端已经分好了，卡片照说。

## 4. 验收清单

- [ ] 浅色 / 深色都读得清，强调色各只出现一次
- [ ] 畸形 `arguments`、`error` 存在、`metadata` 缺失 —— 三种情况都退化成通用行且不报错
- [ ] 会话回放（刷新页面后重新渲染历史）与直播流里长得一样
- [ ] 长标题、超长无空格英文串不撑破布局
- [ ] 键盘可达：链接可 Tab，焦点环用强调色 2px
